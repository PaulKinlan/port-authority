AI router

Attack lab: this page is a hostile site

The AI router lets a site use your model account without seeing your API key. The site sits in the middle the whole time: it embeds the router's frame, and it opens the router's window. So the question is what a site that wants your key can do from there.

This page is that site. It embeds the real router and attacks it. Every attack below runs for real, in your browser, when you press its button. The code that runs is shown beside it. Everything this page manages to collect is shown at the bottom, so you can read it yourself.

Before you start

  1. You need an account at the router. The key can be made up, such as sk-made-up-0000. A key is only checked when a prompt is sent, and most of these attacks send none.
  2. Several attacks open the router window. Choose an account there and press Allow, as you would for a site you trusted. Give it 5 requests.
  3. This page started recording before the router's script loaded. It has recorded every message its window was sent, every port it was ever given, and every message on those ports.

You are safe to try this with a real key: that is what the page is here to show. But it is an experiment, so use a key you can cancel.

    Why they fail

    • A page cannot read a frame or a window from another address. The browser refuses, with a SecurityError.
    • A message goes only to the address the sender named. The router window posts the key line with the router's address as the target. A decoy frame at any other address is sent nothing.
    • A message is marked with the address it really came from. This page can post the router's own messages at the frame. They arrive marked with this page's address, and the frame ignores them.
    • A port has two ends and cannot be copied. The window made the key line and kept one end. The browser put the other end in the frame. This page never held either.
    • The count is kept where this page cannot reach. It is in the frame's own storage for this site. Clearing this page's storage does not touch it.

    The one attack that works is the look-alike window. Nothing in a browser stops a site opening a window that looks like the router's. The address bar is the only thing that tells you, and that is why the real window never asks for a key.
