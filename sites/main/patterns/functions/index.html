Port patterns / More things a port can carry

Pass a function to another origin

What you are looking at

A function cannot be cloned, but a port can stand in for one. Wrap the function in a channel, send the other end, and the receiver gets something it can call. Arguments can be functions too, the same way. Close the port and the function stops existing for them. This is how Comlink works underneath.

The code

const lend = (fn) => {
  const { port1, port2 } = new MessageChannel();
  port1.onmessage = (e) => fn(...e.data);
  return { port: port2, revoke: () => port1.close() };   // send port, keep revoke
};
const borrow = (port) => (...args) => port.postMessage(args);

Using it

// a photo site. A resizing tool from another company runs in a frame.
// The site lends it a function that moves the site's own progress bar.
const onProgress = (done, total) => { bar.max = total; bar.value = done; };
const grant = lend(onProgress);
tool.contentWindow.postMessage({ resize: photos }, toolOrigin, [grant.port]);

// in the tool's frame
addEventListener("message", async (event) => {
  if (event.origin !== photoSiteOrigin) return;
  const onProgress = borrow(event.ports[0]);   // a function again
  let done = 0;
  for (const photo of event.data.resize) {
    await shrink(photo);
    onProgress(++done, event.data.resize.length);  // runs in the photo site's page
  }
});

// the person cancels: the tool's later calls do nothing, and it is told nothing
cancelButton.onclick = () => grant.revoke();

Where you would use it

A real case. A photo site uses a resizing tool from another company, which runs in a frame on its own origin. The site wants its own progress bar to move while the tool works, so it lends the tool an onProgress function. The tool calls it after each photo, and the call runs in the site's page, where the bar is. The tool cannot read the function or reach the bar. When the person cancels, the site calls revoke(), which closes its end of the channel, and the tool's later calls do nothing.

How it works

A function cannot be cloned or transferred. A port can. So a function is passed by keeping it at home and sending a port that calls it: the receiver posts arguments, your side runs the function and posts back the result.

The function never leaves. It still sees your variables and runs with your origin's authority. The other side can call it and can't read it.

Close the port and the function is taken back. The other side's next call goes nowhere. JavaScript has no other way to revoke a callback.

Step by step

What each press of Next does in the demo at the top.

  1. Lend onTick(). A channel is created wrapping onTick(), and one end is sent to the other origin as a callable handle.
  2. Start the countdown. The other origin starts ticking and calls onTick() on each tick; every call runs back here.
  3. Take the function back. This page closes its end of the port. The countdown carries on over there, but its calls no longer arrive.

An event listener that lives on another origin

The idea: Callbacks and event listeners across origins.

What you are looking at

addEventListener takes a function, and a function cannot cross origins. A port can. This page listens to its own button and posts each press down a port. The analytics frame on another origin counts presses of a button it cannot see, in a page it cannot read. Close the port and it is unsubscribed.

The code

// the other origin wants: button.addEventListener("click", theirFunction)
const { port1, port2 } = new MessageChannel();
button.addEventListener("click", () => port1.postMessage({ type: "click", at: Date.now() }));
analytics.postMessage({ cmd: "listen" }, "*", [port2]);
// unsubscribe them
port1.close();

Step by step

What each press of Next does in this demo.

  1. Let analytics listen. A port goes to the analytics frame. Presses of this page's button will be posted down it.
  2. Press the page's button. The press is heard on the other origin.
  3. Press the page's button. And again.
  4. Unsubscribe analytics. This page closes the port.
  5. Press the page's button. The button still works here. The other origin hears nothing.

Lend one method of an object, and not the object

The idea: Exposing one method of an object rather than the object.

What you are looking at

This page has a cart with three methods: add, clear and total. A badge from another origin needs the total. It is given a port that calls cart.total() and nothing else. The badge can ask for the total as often as it likes. It cannot add, and it cannot clear, because the port it holds doesn't offer those methods.

The code

const cart = { items: [], add(item) {…}, clear() {…}, total() {…} };
const { port1, port2 } = new MessageChannel();
port1.onmessage = ({ data }) =>
  port1.postMessage(data.call === "total" ? { result: cart.total() } : { error: "not on this port" });
badge.postMessage({ cmd: "port" }, "*", [port2]);

Step by step

What each press of Next does in this demo.

  1. Lend the badge cart.total. The badge gets a port that reaches one method.
  2. Add tulips to the cart. This page uses its own cart, with all its methods.
  3. Badge: ask for the total. The badge calls total through its port.
  4. Badge: try to clear the cart. The badge asks for a method it was not lent.

Call another origin's object as if it were local, in about twenty lines

The idea: Libraries in the Comlink family, which wrap exactly this.

What you are looking at

Libraries such as Comlink turn a port into something you call like an ordinary object. This is that idea at its smallest. On this page, wrap(port) returns a Proxy. Reading a property extends a path, and calling it posts the path and the arguments down the port and returns a promise. In the frame, expose(api, port) walks the path, calls the function, and posts back the result or the error. The walk only follows properties the object itself has. Without that check, a caller could ask for constructor and reach Function, which the Comlink page shows happening in Comlink 4.4.2.

The code

// this page
function wrap(port) {
  let last = 0; const waiting = new Map();
  port.onmessage = ({ data }) => {
    const { resolve, reject } = waiting.get(data.id); waiting.delete(data.id);
    "error" in data ? reject(new Error(data.error)) : resolve(data.result);
  };
  const at = (path) => new Proxy(() => {}, {
    get: (_, key) => key === "then" ? undefined : at([...path, key]),
    apply: (_, __, args) => new Promise((resolve, reject) => {
      waiting.set(++last, { resolve, reject });
      port.postMessage({ id: last, path, args });
    }),
  });
  return at([]);
}
const shop = wrap(port);
await shop.basket.total();

// the frame on another origin
function expose(api, port) {
  port.onmessage = async ({ data: { id, path, args } }) => {
    try {
      let owner = null, target = api;
      for (const key of path) {
        if (!Object.hasOwn(target, key)) throw new Error("nothing called " + path.join("."));
        owner = target; target = target[key];
      }
      port.postMessage({ id, result: await target.apply(owner, args) });
    } catch (err) { port.postMessage({ id, error: err.message }); }
  };
}

Step by step

What each press of Next does in this demo.

  1. Wrap the port. The frame exposes an object on its end. This page wraps the other end in a Proxy.
  2. shop.add(2, 3). A call that looks local. The path and the arguments went down the port, and 5 came back.
  3. shop.basket.add("lilies"). A method two levels down. It changes the basket that lives in the frame.
  4. shop.basket.total(). The total is worked out in the frame, from the basket as it is now.
  5. shop.reserve(). This method throws in the frame. The promise on this page rejects with the same message.
  6. shop.constructor("return 1"). The object has no property of its own called constructor, so the frame refuses.

Things to try

  • Lend the function and watch each call from the other origin run here.
  • Take it back while the countdown is still running over there. Their calls stop arriving.

Common mistakes

  • Every call is asynchronous, even if the function is not.
  • Arguments and results are copied. An object passed through is a snapshot, not a reference.
  • Nothing collects a port when the far side forgets it. Close proxies you are done with.
