Port patterns / More things a port can carry

Let another origin paint on your page

What you are looking at

The painter is a frame on another origin. It draws on a canvas of its own and sends each finished frame down a port as an ImageBitmap, which is moved and not copied. This page shows each one in a canvas it owns. The painter cannot read or touch anything here. Handing over the canvas's own drawing surface would be shorter, but Chrome crashes a frame in another process that draws on one, so that is kept for workers.

The code

// the other origin: draw, then send the finished frame
const mine = new OffscreenCanvas(width, height);
const ctx = mine.getContext("2d");
requestAnimationFrame(async function draw(t) {
  paint(ctx, t);
  const frame = await createImageBitmap(mine);
  port.postMessage({ frame }, [frame]);       // moved
  requestAnimationFrame(draw);
});

// this page: show it
const show = canvas.getContext("bitmaprenderer");
port.onmessage = ({ data }) => show.transferFromImageBitmap(data.frame);

Using it

// a shoe shop's product page. The 3D viewer is a frame from another company.
const channel = new MessageChannel();
const port = channel.port1;
viewer.contentWindow.postMessage("paint", viewerOrigin, [channel.port2]);

// the viewer cannot measure the shop's canvas, so the page sends width and height
port.postMessage({ width: canvas.width, height: canvas.height });

// the person picks red. The viewer's paint() uses it from the next frame.
redSwatch.onclick = () => port.postMessage({ colour: "red" });

// the person leaves the product. A closed port tells the viewer nothing,
// so the page asks it to stop, and frees frames that are already on the way.
closeButton.onclick = () => {
  port.postMessage({ stop: true });
  port.onmessage = ({ data }) => data.frame.close();
};

Where you would use it

A real case. A shoe shop shows a 3D view of each shoe, drawn by a viewer from another company. The viewer runs in a frame on its own origin and sends each finished picture down a port, and the shop shows it in a canvas inside its own product layout. The shop sends the canvas size and the colour the person picks down the same port. The viewer's code never runs in the shop's page, so it cannot read the basket or the person's details. When the person leaves the product, the shop asks the viewer to stop and closes any pictures that still arrive.

How it works

There are two ways to let someone else draw in your page. Which one to use depends on where the drawer runs.

For a worker: canvas.transferControlToOffscreen() splits a canvas in two. The element stays in your page, and its drawing surface becomes an OffscreenCanvas that can be transferred. The worker draws, and the pixels appear in your element without passing through your main thread, so the canvas keeps animating while your page is busy.

For a frame on another origin: the frame draws on an OffscreenCanvas of its own, turns each finished frame into an ImageBitmap and transfers it down a port. Your page shows it with a bitmaprenderer context. A bitmap is moved, so no pixels are copied on the way.

Either way the drawer cannot read your page or see the rest of your DOM. It fills one rectangle you chose and nothing else.

A chart drawn by another origin, inside your layout

The idea: A chart, map or 3D viewer supplied by another origin that renders into your layout without an iframe's box.

What you are looking at

The chart maker is a sandboxed frame with an opaque origin. It stands in for a charting service from another site. This page gives it a port and sends it numbers. The chart maker draws the bars on a canvas of its own and sends back each finished frame as an ImageBitmap, which this page shows in a canvas it owns. The chart maker never sees the page, and its code never runs in this page.

The code

const show = canvas.getContext("bitmaprenderer");
chartMaker.onmessage = ({ data }) => show.transferFromImageBitmap(data.frame);
chartMaker.postMessage({ size: [460, 230], numbers });
// later, new figures: the chart redraws itself
chartMaker.postMessage({ numbers: [12, 30, 22, 41, 17] });

// the chart maker, after each redraw
const frame = await createImageBitmap(mine);
port.postMessage({ frame }, [frame]);

Step by step

What each press of Next does in this demo.

  1. Ask the chart maker for a chart. The size and the first numbers go to the other origin. It draws the bars and sends back finished frames.
  2. Send new numbers. This page posts new figures. The chart maker animates to them.
  3. Send new numbers. And again. Only numbers go one way, and only pixels come back.

The same heavy drawing, on the page's thread and then on a worker's

The idea: Moving heavy rendering to a worker.

What you are looking at

Both canvases get the same job: two seconds of zooming into the Mandelbrot set, frame after frame. Drawn by the page, the page can do nothing else: its counter stops, and you see only the last frame. Drawn by a worker that was handed the canvas, every frame appears as it is finished, and the page's counter keeps going.

The code

const surface = canvas.transferControlToOffscreen();
worker.postMessage({ surface }, [surface]);

// the worker: draw as hard as you like, the page is not waiting for you
onmessage = ({ data }) => { const ctx = data.surface.getContext("2d"); for (;;) drawNextFrame(ctx); };

Step by step

What each press of Next does in this demo.

  1. Draw on the page's thread. The page draws for two seconds. Watch its counter: it stops.
  2. Draw in the worker. The worker draws the same frames into a canvas it was handed. The counter keeps going.

Common mistakes

  • In Chrome, do not send the surface from transferControlToOffscreen() to a frame on another site or to a sandboxed frame. Those run in another process, and the frame crashes on its first draw. The message arrives and getContext() succeeds, so nothing warns you. Send it to a worker, or send bitmaps.
  • Once control is transferred, the page can no longer draw on that canvas or read it back.
  • The receiver decides the bitmap size. Tell it your size and pixel ratio over the port.
  • Close an ImageBitmap you are not going to show. It holds memory the garbage collector does not count.
