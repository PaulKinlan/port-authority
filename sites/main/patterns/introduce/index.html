Port patterns / The six basic patterns

Connect two sites to each other, then remove yourself

What you are looking at

A port can be passed on by whoever holds it. So a third party that knows two sites can make a channel, give each of them an end, and step away. The three windows are three different sites, and each address is in its bar. So that you can see all three at once, each is shown as a frame inside this page. A site cannot go and find the introducer. Two windows that have nothing to do with each other cannot reach each other in a browser at all. A first line exists only because one window opened the other, or one is a frame inside the other. So an introducer is a window a site opens, or a window that opens the sites, or a page that holds them as frames. This page stands in for that: it holds all three, and hands Site A and Site B their first lines. Close the introducer and the other two do not notice. This is how the hub works.

The code

// in the introducer, which holds a port to each side
const { port1, port2 } = new MessageChannel();
toLeft.postMessage({ meet: "right" }, [port1]);
toRight.postMessage({ meet: "left" }, [port2]);
// nothing else to do. It can close.

Using it

// a print shop wants the person's photos. When the person presses Choose photos
// it opens a picker window, and that is what lets the shop post to the picker.
const picker = window.open(pickerUrl, "", "popup");
const line = new MessageChannel();
// once the picker says it is ready
picker.postMessage("line", pickerOrigin, [line.port2]);  // the picker keeps this as toLeft

// In the picker, the person chooses a photo store. The picker opens it in a
// window, posts it a port in the same way, and keeps the other end as toRight.
// Then the picker runs the code above and closes.

// the print shop hears on its line to the picker
line.port1.onmessage = (e) => {
  const store = e.ports[0];             // port1 of the new channel
  line.port1.close();                   // the picker is not needed again
  show("Connected to " + e.data.meet);
  store.onmessage = (m) => addToOrder(m.data.photo);
  store.postMessage({ want: "photos" });
};

Where you would use it

A real case. A print shop needs photos that the person keeps with a photo storage site. The shop does not know every storage site, so it opens a picker window, and the picker opens the storage site that the person chooses. The picker was opened by the shop and it opened the storage site, so it can hold a port to each. It makes a new channel, sends one end to the shop and one to the storage site, and closes. The shop then asks the storage site for photos directly, and the picker sees none of it.

How it works

The introducer knows two parties who do not know each other. It makes a channel and posts one end to each. The two can now talk directly. The introducer kept neither end, so it can't read the messages and it can go away.

A broker normally stays in the path of every message. Here it is only needed for the introduction.

Think of two sites in two tabs. Neither has a reference to the other's window, so neither could have reached the other alone. The introducer has a line to both and chooses to connect them. In the demo the three sites are frames in this page, so this page hands out the first two lines, one from each site to the introducer.

How does a site come to have a line to the introducer in the first place? Not by looking for it. A browser gives a page a handle to another window in three ways only: the page opened that window, the page was opened by it, or one is a frame inside the other. A page can post a port to a window it has a handle to, and that is the first line. Two tabs that a person opened by hand, on two different sites, have none of these. Nothing in a browser will connect them, and no introducer can reach them.

So in practice an introducer is one of three things. It is a window that a site opens, as this site's hub is, and as the router's window is. Or it is a window that opens the sites. Or it is a page that holds the sites as frames. Pages from one site can also find each other with a BroadcastChannel or a SharedWorker, but only pages from that same site. A server that both sites talk to can pass messages between them, but that is a connection through the server, and not a port.

Step by step

What each press of Next does in the demo at the top.

  1. Connect Site A to the introducer. Site A gets a private line to the introducer. Between real windows that takes one of them having opened the other. Here this page hands the line over. Site B is still separate.
  2. Connect Site B to the introducer. Site B gets its own line to the introducer. A and B still cannot reach each other.
  3. Introduce them. The introducer makes a new channel and sends one end to Site A and one end to Site B. The yellow direct line appears underneath.
  4. Site A says hello. Site A talks directly to Site B on the yellow cable. Nothing passes through the introducer.
  5. Site B says hello. Site B answers directly on the same yellow cable.
  6. Close the introducer. The introducer's window is closed and its dark cables vanish. The yellow direct line stays.
  7. Site A says hello. Site A still reaches Site B. The line never belonged to the introducer.

Two vendors' widgets, wired together by the page that embeds them

The idea: Connecting two widgets from different vendors on one page without either loading the other's code. A parent page that wires its iframes together and then stays out of their conversation.

What you are looking at

A list of places from one vendor and a map from another, each in its own frame on its own origin. Neither has heard of the other and neither loads the other's code. The page that embeds them makes a channel, and gives each widget an end. Pick a place in the list and the map moves, with nothing passing through the page.

The code

const { port1, port2 } = new MessageChannel();
listFrame.postMessage({ cmd: "port" }, "*", [port1]);
mapFrame.postMessage({ cmd: "port" }, "*", [port2]);
// that is all the integration code there is

Step by step

What each press of Next does in this demo.

  1. Wire the two widgets together. Each widget gets one end of a channel. This page keeps neither.
  2. List: pick the next place. The list tells the map directly. The map answers the list.
  3. List: pick the next place. Again. Nothing passes through the page in the middle.

A picker that connects a shop to the florist the person chose, then closes

The idea: A picker or hub that connects a site to a tool the person chose, then closes. This site's hub does that.

What you are looking at

Two florists have each registered with the picker. The shop holds a port to the picker and knows neither florist. The shop asks for someone who can send flowers. The picker waits for the person to choose. Then it makes a channel, sends one end to the chosen florist and the other to the shop, and keeps neither. After that the picker can be closed. The order goes from the shop to the florist on the new channel, and the florist that was not picked hears nothing. The hub on this site is this, with the list of tools kept on a server.

The code

// the shop
picker.postMessage({ want: "send flowers" });
picker.onmessage = ({ data, ports: [florist] }) => {
  florist.postMessage({ order: "twelve tulips" });      // straight to the florist
};

// the picker, when the person has chosen
const { port1, port2 } = new MessageChannel();
tools.get(choice).postMessage({ introduced: "the shop" }, [port1]);
shop.postMessage({ tool: choice }, [port2]);
// it kept neither end, so it can close

Step by step

What each press of Next does in this demo.

  1. Shop: ask for someone to send flowers. The shop asks the picker. The picker knows two florists that can, and waits for the person.
  2. Person: pick Petal Post. The picker makes a channel and gives one end to Petal Post and the other to the shop.
  3. Close the picker. The picker's frame is destroyed. The line between the shop and the florist is still there.
  4. Shop: order twelve tulips. The order goes straight to Petal Post, and the answer comes straight back. Rose and Thorn hears nothing.

Things to try

  • Introduce them, close the introducer, then make both sites talk. Count the dots that pass through the middle box: none.
  • Press Start again and close the introducer first. The sites can never meet.

Common mistakes

  • Each side needs a line to the introducer before it can be introduced, and that line comes from opening a window or holding a frame. An introducer cannot reach a tab it has no handle to.
  • The introducer cannot take the introduction back. If it needs to, it should keep a link in the chain and forward, as in the attenuate pattern.
  • Nothing tells either side that the other has gone. Send a ping and treat silence as the answer.

Measured

Chromium 157: messages keep flowing between two frames on different sites after the introducing frame, on a third site, is removed from the document. Other browsers are being filled in from the lab's results.
