Port patterns / More things a port can carry

Back-pressure across three origins

What you are looking at

This page hands its stream to a frame on another origin. That frame transforms it and hands the result to a frame on a third origin, down a port it holds to that frame. Nothing is buffered without limit: pause the reader and, a few chunks later, the source stops being asked for more.

The code

// the transformer, on its own origin
port.onmessage = ({ data }) => {
  const out = data.readable.pipeThrough(new TransformStream({ transform: shout }));
  toReader.postMessage({ readable: out }, [out]);   // a port to the third origin
};

Using it

// a recorded meeting page, a caption styler from a second company, a player from a third
const toStyler = new MessageChannel(), between = new MessageChannel();
styler.contentWindow.postMessage({}, stylerOrigin, [toStyler.port2, between.port1]);   // port and toReader
player.contentWindow.postMessage({}, playerOrigin, [between.port2]);
// the page: a stream that makes a line only when it is asked for one
const readable = new ReadableStream({ pull(c) { c.enqueue(nextLine()); } }, { highWaterMark: 0 });
toStyler.port1.postMessage({ readable }, [readable]);

// the styler: shout is its transform
const shout = (line, controller) => controller.enqueue(line.toUpperCase());

// the player: show one caption for two seconds, then read the next
port.onmessage = async ({ data }) => {
  const reader = data.readable.getReader();
  for (;;) {
    if (paused) await resumed();                // the person pressed pause
    const { value, done } = await reader.read();
    if (done) return;
    await showFor(value, 2000);
  }
};
// While it is paused nothing is read. A few lines later pull() stops being called in the page.

Where you would use it

A real case. A page plays a recorded meeting and holds the transcript. A frame from a second company styles each line as a caption, and a player frame from a third company shows one caption at a time. The page gives the styler a port to the player, so styled lines go to the player and do not come back through the page. When the person pauses the player it stops reading, and a few lines later the page stops being asked for more. No stage sends a pause message to another, and only a few lines are in flight at any time.

How it works

Three origins in a row: a source, a transformer and a reader. The source's stream is transferred to the transformer, which pipes it through a TransformStream and transfers the result to the reader.

Each stream has a small queue. When the reader stops reading, its queue fills, the transformer's writes stop being accepted, its queue fills, and the source stops being asked for more. Pausing the last stage stops the first, across two origin boundaries, with no message from you.

Start reading again and demand flows back the other way. The source resumes a few chunks later.

Step by step

What each press of Next does in the demo at the top.

  1. Connect the three origins. Channels are opened from this page to the transformer, and from the transformer to the reader.
  2. Start the pipe. A ReadableStream leaves this page, passes through the transformer, and reaches the reader.
  3. Pause the reader. The reader stops pulling. Back-pressure travels upstream and stops the source a few chunks later.
  4. Let the reader continue. The reader resumes pulling, and the source starts producing again.

Three parties each supply one stage, and none of them sees the others

The idea: Processing chains where each stage is supplied by a different party: decrypt, then decode, then display.

What you are looking at

A zipped order needs unzipping, turning from bytes into text, and its card number hiding before it is shown. Each of those is a stream stage supplied by a different origin. This page asks each for a stage, joins the three end to end and sends the file through. This page holds both ends of every stage, so the data comes back here between one stage and the next. Each party sees only what flows through its own stage, and none of them needs to know the others exist.

The code

// each party
const stage = new TransformStream({ transform(chunk, out) { out.enqueue(work(chunk)); } });
parent.postMessage({ readable: stage.readable, writable: stage.writable }, "*", [stage.readable, stage.writable]);

// this page
zippedFile.pipeThrough(unzip).pipeThrough(decode).pipeThrough(redact).pipeTo(screen);

Step by step

What each press of Next does in this demo.

  1. Ask each party for a stage. Three origins each hand over both ends of one transform.
  2. Pour a zipped order through all three. Bytes go in at one end. Readable text with the card number hidden comes out of the other.

Things to try

  • Start the pipe, pause the reader and watch the source's counter stop a few chunks later.
  • Resume and watch it pick up.

Common mistakes

  • The queues mean a few chunks are always in flight. Do not assume pause is instant.
  • Every stage must stay alive. See why a stream does not survive its introducer.
