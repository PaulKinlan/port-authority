Comlink, rebuilt for today's platform

Comlink made a worker feel like a local object. It was written when ports could carry far less than they can now. This page takes it apart, then puts it back together with what the platform has gained.

The result is one file with no dependencies, hawser.js (a hawser is the rope that ties a ship to a port; the name is a placeholder). Every demo below runs it between this page and real pages on other origins, and where it helps, runs Comlink 4.4.2 beside it.

How Comlink works

Comlink is about 650 lines, and the idea fits in five steps.

  1. wrap(port) returns a Proxy around an empty function. Reading a property does nothing but return another proxy that remembers the path so far.
  2. Calling it, awaiting it, assigning to it or using new posts one of six messages down the port: GET, SET, APPLY, CONSTRUCT, ENDPOINT or RELEASE, with the path and a random id.
  3. expose(object, port) listens on the other end, walks the path on the real object, does the thing, and posts the result back with the same id.
  4. Values go through structured clone. To send something by reference, such as a callback, you mark it with proxy(). Comlink then makes a new MessageChannel, exposes the value on one end, and transfers the other end in its place. Every proxied value is its own port.
  5. Extra types are handled by named transfer handlers, which is how thrown errors are flattened and rebuilt.
worker.postMessage({ id: "4f1c…", type: "APPLY", path: ["math", "add"],
  argumentList: [{ type: "RAW", value: 1 }, { type: "RAW", value: 2 }] });
// and back
port.postMessage({ id: "4f1c…", type: "RAW", value: 3 });

That design has aged well. What has changed is everything around it.

A call should fail when nobody is there to answer

Comlink keeps a map of promises waiting for replies and nothing ever empties it. If the worker crashes or the frame is closed, every call in flight waits forever. Here three things notice a departure. A page that is closing says goodbye on every link it holds. The port's new close event is used where the browser has it. And an optional heartbeat catches a side that crashed without a word. Whichever comes first, every pending call rejects with a LinkClosedError, and so does every later one. Ask the question, then remove the frame.

const api = wrap(port, { heartbeat: 1000, timeout: 30_000 });
try { await api.slow(); }
catch (error) { // LinkClosedError, or TimeoutError }
closed(api).then(() => showOffline());

Pass an AbortSignal and it arrives as one

An AbortSignal cannot be cloned, so with Comlink there is no way to cancel work you started. Here a signal in the arguments is swapped for a small token. The far side gets a real signal of its own, and when yours aborts, theirs does, with the same reason. The call also rejects on this side at once. If the caller simply disappears, every signal it sent is aborted, so work is never left running for nobody.

const controller = new AbortController();
const job = api.count(20, controller.signal);
cancelButton.onclick = () => controller.abort();

// on the other origin, nothing special
async count(to, signal) {
  for (let i = 1; i <= to; i++) { signal.throwIfAborted(); await step(i); }
}

Use an answer before it has arrived

With Comlink, each step that returns an object costs a full trip there and back, and a new port. Here a call returns something you can keep calling into straight away. Everything queued in the same tick is sent as one message, the far side runs the steps in order against the real values, and only one port is ever used. Across a worker boundary the saving is small. Across a slow hop, such as a relay or a WebRTC line, it is the difference between one wait and three.

// one message out
const title = await api.open("ideas").latest().title();

// Comlink: three round trips, three ports
const notebook = await old.open("ideas");
const note = await notebook.latest();
const title = await note.title();

Loop over something that is still happening elsewhere

An async generator on the far side can be read with for await on this side. Nothing is produced until it is asked for, so a slow reader slows the writer. Leave the loop and the generator's finally block runs over there. It also runs if the reader is garbage collected or its page goes away. For bytes, return a ReadableStream and it is moved across whole.

// there
async *ticks() {
  try { for (;;) yield await nextTick(); }
  finally { stopTicking(); }
}
// here
for await (const tick of api.ticks()) {
  if (enough(tick)) break; // stopTicking() runs on the other origin
}

Hand someone part of what you hold, and take it back

Comlink will walk any path a caller sends, including constructor, which on a function is a way to run arbitrary code in the exposing page. That is fine for your own worker and not for another origin. Here a path cannot leave the object's own surface, expose() can list the only paths allowed, and port() asks the owner to mint a new port for a third party that reaches less than you can. The guest talks to the owner directly. Abort the signal and its port dies.

expose(api, port, { only: ["counter", "search"] });

// a holder passes on less than it has
const revoke = new AbortController();
const forGuest = await port(api.counter, { only: ["read"], signal: revoke.signal });
guestWindow.postMessage("here", guestOrigin, [forGuest]);
revoke.abort(); // later

Lifetimes that end when a scope does

An object made for you on the far side is yours to end. Dispose of the proxy, with using or by hand, and its Symbol.dispose method is called over there. Forget to, and a FinalizationRegistry does it when the proxy is collected. Close the link, or lose it, and everything it was holding is disposed at once. Functions, class instances and iterators all share the one port, with a reference count kept by the side that owns them.

{
  using session = await new api.Session("ada");
  await session.who();
} // Session[Symbol.dispose]() has now run on the other origin

What is still out of reach

  • The result of a call is not a real Promise. It can be awaited, passed to Promise.all and given .then, but instanceof Promise is false, because it also has to be something you can keep calling into.
  • A chain only shares a message if it is written in one tick. Hold a result, wait, then call into it and it still works, by waiting for the answer first.
  • Garbage collection is a hint and not a promise. Anything that must be released on time should be disposed of on purpose.
  • The heartbeat is a timer, and browsers slow timers in background tabs. Use it to notice a dead frame, not to measure one.
  • Everything is asynchronous. A blocking call needs shared memory and a cross-origin isolated page, which is what the isolated room is for.
  • Only tested in Chromium so far, plus the same suite in Node, where MessageChannel behaves the same way.

The whole surface

import { expose, wrap, connect, port, closed,
         share, give, transfer, offer, accept } from "/hawser.js";

expose(target, endpoint, { only, heartbeat, timeout, signal, onclose })
wrap(endpoint, { heartbeat, timeout, signal, onclose })
connect(target, endpoint)   // both directions: { remote, close, revoke, closed }
port(remote, { only, signal }) // a narrowed, revocable port to pass on
closed(remote)              // promise for why the link ended
share(object)               // send by reference
give(object)                // by reference, and theirs to dispose
transfer(buffer)            // move, do not copy
offer(window, origin)       // give a window a port, origin required
accept(origins, callback)   // take ports only from these origins
