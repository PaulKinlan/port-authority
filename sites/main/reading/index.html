Further reading on message ports

This site builds on a lot of other people's work. Here are 186 places to read more about MessageChannel, MessagePort, postMessage, transferable objects and SharedWorker: the reference pages, the specifications, articles, libraries, talks and research papers. Each link has one line on what it covers.

Not much has been written about message ports on their own. Most of the writing and nearly all of the research is about window.postMessage and workers, so those are here too.

The links were last checked on 2026-11-21. If one is broken, or something good is missing, please open an issue.

Specifications

The standards that define the behaviour.

  • HTML Standard: Web messaging WHATWG The current specification for cross-document messaging, channel messaging and BroadcastChannel.
  • HTML Standard: Channel messaging WHATWG MessageChannel and MessagePort, including the rule that a port with a listener is not garbage collected.
  • HTML Standard: Ports as the basis of an object-capability model on the web WHATWG A short section of the standard that describes a port as a permission that can be handed on.
  • HTML Standard: Security of cross-document messaging WHATWG What the standard asks authors to check when they receive a message.
  • HTML Standard: Safe passing of structured data WHATWG The definition of serializable objects, transferable objects and structured clone.
  • HTML Standard: Web workers WHATWG Dedicated and shared workers, and the implicit port each dedicated worker has.
  • Streams Standard: Transferable streams WHATWG How a stream is moved to another context: the two halves are joined by a message port.
  • Transferable streams explainer WHATWG The reasons for making streams transferable, with examples.
  • Service Workers W3C Defines postMessage between pages and service workers.
  • Web Locks API W3C The specification for locks shared by tabs and workers of one origin.
  • Client-Side Storage Partitioning W3C Privacy Community Group The plan for partitioning storage and communication APIs, including SharedWorker and BroadcastChannel, by top-level site.
  • The Storage Access API W3C Privacy Community Group The repository for the API an embedded frame uses to ask for unpartitioned access.
  • HTML5 Web Messaging (W3C Recommendation, 2015) W3C, 2015 The older W3C snapshot of the same text. It has been superseded by the HTML Standard and is useful for history.

Capabilities and RPC

A port gives its holder the ability to send to one place, and it can be handed on. That is the idea behind object-capability security, which has a long literature.

  • Robust Composition: Towards a Unified Approach to Access Control and Concurrency Control Mark S. Miller, 2006 The thesis that sets out object capabilities and promise pipelining. Cap'n Proto, Cap'n Web and CapTP (Capability Transport Protocol) build on it.
  • Cap'n Proto: RPC Protocol Kenton Varda A capability-based RPC protocol in which a reference to a remote object can be passed in a call.
  • Cap'n Web: a new RPC system for browsers and web servers Kenton Varda and Steve Faulkner, Cloudflare, 2025 The same model in plain JavaScript and JSON: pass functions and objects by reference, in both directions.
  • OCapN OCapN pre-standardization group Work on a shared protocol for object capabilities across a network.
  • Endo Endo Documentation for Hardened JavaScript, compartments and the eventual-send API.

Security guides and write-ups

Almost all of these are about window.postMessage listeners that do not check who sent the message. A private MessagePort avoids that class of bug, because only the holder of the other end can send to it.

Research papers: security of messaging

I found no paper that is only about MessageChannel. The research is about postMessage, frames and workers, and several papers cover ports as part of that.

  • Protection and Communication Abstractions for Web Browsers in MashupOS Wang, Fan, Howell and Jackson, SOSP, 2007 Proposed browser abstractions for isolated content from different sites to talk to each other, shortly before postMessage shipped.
  • Securing Frame Communication in Browsers Barth, Jackson and Mitchell, USENIX Security, 2008 Found a confidentiality flaw in the first postMessage design. The fix is the target origin argument used today.
  • Attacks on JavaScript Mashup Communication Barth, Jackson and Li, W2SP, 2009 Shows how libraries layered on postMessage and similar channels let one side compromise the other. PDF.
  • The Emperor's New APIs: On the (In)Secure Usage of New Client-side Primitives Hanna, Shin, Akhawe, Boehm, Saxena and Song, W2SP, 2010 Studies postMessage protocols in Facebook Connect and Google Friend Connect and finds missing origin checks.
  • Privilege Separation in HTML5 Applications Akhawe, Saxena and Song, USENIX Security, 2012 Splits an application into unprivileged parts that can only reach a small privileged parent by postMessage.
  • Treehouse: JavaScript Sandboxes to Help Web Developers Help Themselves Ingram and Walfish, USENIX ATC, 2012 Runs untrusted scripts in web workers with a virtual DOM, with every request checked as it crosses by message.
  • The Postman Always Rings Twice: Attacking and Defending postMessage in HTML5 Websites Son and Shmatikov, NDSS, 2013 A study of message receivers on the Alexa top 10,000 sites. Many checked the origin incorrectly or not at all.
  • Protecting Users by Confining JavaScript with COWL Stefan, Yang, Marchenko, Russo, Herman, Karp and Mazières, OSDI, 2014 Adds labels to browser contexts and to the messages they exchange, so a page can share data with code it does not trust.
  • ZigZag: Automatically Hardening Web Applications Against Client-side Validation Vulnerabilities Weissbacher, Robertson, Kirda, Kruegel and Vigna, USENIX Security, 2015 Learns what normal messages look like and blocks ones that do not fit, to protect weak postMessage receivers.
  • How the Web Tangled Itself: Uncovering the History of Client-Side Web (In)Security Stock, Johns, Steffens and Backes, USENIX Security, 2017 Twenty years of archived pages, including how postMessage use and missing origin checks grew over time.
  • Study and Mitigation of Origin Stripping Vulnerabilities in Hybrid-postMessage Enabled Mobile Applications Yang, Huang, Gu and Mendoza, IEEE S&P, 2018 postMessage between native code and a WebView loses the origin of the sender. This is the project page.
  • Site Isolation: Process Separation for Web Sites within the Browser Reis, Moshchuk and Oskov, USENIX Security, 2019 How Chrome puts each site in its own process. Explains what it took to keep postMessage working between frames in different processes.
  • PMForce: Systematically Analyzing postMessage Handlers at Scale Steffens and Stock, ACM CCS, 2020 Automated analysis of message handlers on the top 100,000 sites. It found 111 handlers it could exploit automatically.
  • Careful Who You Trust: Studying the Pitfalls of Cross-Origin Communication Meiser, Laperdrix and Stock, ACM AsiaCCS, 2021 Maps which sites trust which others through postMessage and CORS (Cross-Origin Resource Sharing), and how far a flaw in one site reaches.

Research papers: timing, workers and concurrency

  • Fantastic Timers and Where to Find Them: High-Resolution Microarchitectural Attacks in JavaScript Schwarz, Maurice, Gruss and Mangard, Financial Cryptography, 2017 Builds precise timers from other browser features after performance.now() was made coarse. Message passing between contexts is one of the building blocks.
  • Loophole: Timing Attacks on Shared Event Loops in Chrome Vila and Köpf, USENIX Security, 2017 A page posts messages to itself and times their arrival to learn what other pages on the same event loop are doing.
  • Browsix: Bridging the Gap Between Unix and the Browser Powers, Vilk and Berger, ASPLOS, 2017 Unix processes as web workers, with system calls sent to a kernel on the main thread as messages.
  • Simpler Coordination of JavaScript Web Workers Krauweel and Jongmans, COORDINATION, 2017 Treats workers and postMessage as an actor language and proposes higher-level ways to coordinate them. PDF.
  • Parallel and Distributed Web Programming with Actors Myter, Scholliers and De Meuter, 2018 Spiders.js, an actor framework that uses one model for web workers and for remote machines. PDF.

Web Intents, WebMCP and agents

The ideas the experiments on this site come from: one site asking another to do something for the person, and now an agent doing the asking.

  • Web Intents (W3C Working Group Note) Greg Billock, James Hawkins and Paul Kinlan, W3C, 2013 The last published draft. An intent could carry MessagePorts and other transferables to the service that handled it.
  • Connecting Web Apps with Web Intents James Hawkins, Chromium Blog, 2011 The announcement of the Web Intents work in Chrome.
  • Web Intents Note Published W3C, 2013 The notice that work on the specification had stopped.
  • WebIntents wiki W3C Use cases and notes from the task force.
  • public-web-intents mailing list archive W3C The design discussion, including how a MessageChannel should be set up between client and service.
  • WebAPI/WebActivities Mozilla Mozilla's version of the same idea, built for Firefox OS.
  • Web Actions IndieWeb The IndieWeb community's notes on actions across sites, with a history of earlier attempts.
  • Receiving shared data with the Web Share Target API Chrome for Developers A later API that covers one Web Intents use case: an installed web app registers to receive shares.
  • WebMCP W3C Web Machine Learning Community Group The draft specification for a page to offer tools to an agent.
  • WebMCP in Chrome Chrome for Developers Chrome's documentation for trying WebMCP.
  • MCP Apps Model Context Protocol An MCP extension in which a tool's UI runs in an iframe and speaks JSON-RPC to its host over postMessage.
  • MCP Apps SDK Model Context Protocol The specification and SDK, including the PostMessageTransport class.
  • Agent Client Protocol Agent Client Protocol The protocol between an editor or other client and a coding agent, which the hub on this site carries to a web page.
